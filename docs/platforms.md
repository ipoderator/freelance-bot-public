## 1. FL.ru

### 1.1. `ai.fl.ru/app/developer`: что это за API

**Что видно на странице после входа** (по скриншоту пользователя; без входа страницу не открывали). Вкладки: «Оплата, Расход, Промокод, Управление подпиской, API BETA». Баланс «3 000 кредитов». Карточка «Единый API к моделям и навыкам — Генерация изображений и видео, удаление фона, увеличение и векторизация». Пункты: «Один ключ»; «Автоматизация — встраивайте генерацию в боты, сервисы и внутренние инструменты»; «Асинхронные задачи — REST API: создаёте задачу, результат приходит через статус или webhook»; «Оплата с баланса — кредиты списываются с баланса организации». Блок «API для разработчиков — Ещё нет ни одного ключа» и ссылка «Документация».

**Публичная документация.** Ссылка «Документация» ведёт на **https://ai.fl.ru/api-docs** (HTTP 200). Это одностраничное приложение: текст рисуется скриптом. У маршрута `/api-docs` в публичном бандле `https://ai.fl.ru/assets/index-45f81f70.js` нет признака `requiresAuth`, а у `/app/developer` и других кабинетных страниц он есть. Значит, документация открывается без входа. Её текст и таблица эндпоинтов взяты из публичных статических файлов `index-45f81f70.js` и `api-docs-c45835ea.js`. Сам API не вызывался.

- Заголовок: «API документация — Публичный API генерации изображений и видео».
- Разделы: С чего начать · Авторизация · Эндпоинты · Модели и параметры · Расчёт стоимости · Создание задачи · Входные изображения · Графические навыки · Получение результата · Webhooks · Биллинг и лимиты · Ошибки.
- Базовый URL собирается как `<api-base>/v1/media`.
- **Эндпоинты** (полный список, четыре штуки):

  | Метод | Путь | Назначение (из документации) |
  | --- | --- | --- |
  | GET | `/models` | Каталог моделей, параметров и начальных цен |
  | POST | `/price` | Точная стоимость до запуска задачи |
  | POST | `/tasks` | Создание асинхронной задачи |
  | GET | `/tasks/:id` | Статус задачи и ссылки на результат |

- Модели и навыки: генерация изображений и видео (Seedance, Veo, Wan, MiniMax и др.), `remove-background`, `image-enhancer` (увеличение), `vectorize-scade` (векторизация), `card-product` (карточка товара).
- Авторизация: ключ в заголовке `Authorization: Bearer …`. Оплата кредитами с баланса организации. Лимиты: до 3 задач одновременно, 60 запросов в минуту. Ошибки включают «Недостаточный баланс» и «API недоступен для тарифа».
- Условия оплаты описаны в [оферте на AI-инструменты](https://st.fl.ru/about/documents/offer_credits.pdf) (от 16.02.2026): «Сервис … по адресу https://ai.fl.ru … для генерации текстового, визуального и иного контента с использованием технологий искусственного интеллекта», оплата кредитами или подпиской.

**Вывод.** В документации нет ни одного метода для проектов, заказов, откликов, сообщений или профиля фрилансера. Все четыре эндпоинта относятся к генерации медиа. API на ai.fl.ru **не является** API проектов и откликов FL.ru. Слово «developer» в адресе — не доказательство такого API.

**Другие API FL.ru.** Поиск по сети не нашёл официальной документации API проектов и откликов (запрос «FL.ru официальный API для фрилансеров проекты отклики» от 2026-10-21 вернул только сторонние страницы). В `https://www.fl.ru/robots.txt` путь `/api/` закрыт для всех роботов. Это внутренний путь сайта, и использовать его нельзя. **Вывод: официального API проектов и откликов нет (на 2026-10-21 не найдено).**

### 1.2. RSS-ленты

**Официальный статус.** Подтверждено: «У нас на сайте работает RSS-подписка на новые заказы… В выпадающем списке выберите раздел (категорию) и подраздел (подкатегорию)… Чтобы следить за несколькими разделами сразу — добавьте для каждого свой RSS-канал» ([БЗ 62073](https://knowledge-base.fl.ru/article/62073)). На странице https://www.fl.ru/projects/ есть `<link rel="alternate" type="application/rss+xml" href="/rss/all.xml">` и кнопка «Подписаться через RSS». ID разделов и подразделов взяты из публичного справочника, на котором работает эта кнопка: `https://cdn.fl.ru/assets/legacy/professions.69522ac60b838ae5decd54f04c508716.js`.

**Важная находка про формат URL.** Наблюдение 2026-10-21:
- `https://www.fl.ru/rss/?subcategory=798&category=5` (адрес из брифа) **не фильтрует по подкатегории**. Канал называется «Фри-ланс: Программирование», в нём 60 заказов из всех подкатегорий программирования (веб, Python, 1С, парсинг, Java…). Список элементов совпадает с `https://www.fl.ru/rss/?category=5`.
- `https://www.fl.ru/rss/all.xml?category=5&subcategory=798` **фильтрует**. Канал называется «Фри-ланс: Программирование - Python», и в нём только категория «Программирование / Python».
- `/rss/?category=N` и `/rss/all.xml?category=N` отдают одно и то же.

Поэтому рекомендуется форма `https://www.fl.ru/rss/all.xml?category=N[&subcategory=M]`.

Поток наблюдался такой: в разделе «Программирование» около 7 заказов в сутки по RSS (60 элементов за 13–21 октября).

**Рекомендация для `settings.toml` (`sources.fl.urls`)** — четыре раздела целиком. Это четыре запроса за цикл, нерелевантное отсечёт ранжирование.
```
https://www.fl.ru/rss/all.xml?category=5    # Программирование: Python, парсинг, чат-боты, веб, API, скрипты
https://www.fl.ru/rss/all.xml?category=31   # AI: агенты, боты с AI, LLM
https://www.fl.ru/rss/all.xml?category=41   # Автоматизация бизнеса: AI-автоматизация, интеграции, боты для бизнеса
https://www.fl.ru/rss/all.xml?category=34   # Мессенджеры: Telegram, боты
```
Отдельная лента Python (`…category=5&subcategory=798`) не нужна: она входит в раздел 5. Адрес из брифа тоже равен всему разделу 5.

**Формат элемента** (наблюдение по всем скачанным лентам; элементы, повторяющиеся в разных лентах, посчитаны несколько раз). Поля: `title`, `link`, `description`, `guid`, `category` («Раздел / Подраздел»), `pubDate` (GMT). Особенности, важные для парсера (тикет 03):
- Суффикс в `title` бывает трёх видов: `(Бюджет: 15 000  &#8381;)`, `(Бюджет: 30 000  &#8381;, для всех)` и `(для всех)`. В выборке: 92, 26 и 28 случаев соответственно. Перед `&#8381;` стоит двойной пробел.
- Title лежит в CDATA. Поэтому `&#8381;` приходит **буквальным текстом**, и XML-парсер его не раскодирует. Нужен `html.unescape` или регулярка на обе формы.
- Метка «для всех» означает, что ответ на заказ бесплатный (см. §1.3). Её стоит убрать из title и сохранить в `extra` (например, `extra["for_all"] = True`).
- `description` часто обрезан многоточием «...» (18 из 60 в разделе 5). Переносы строк склеены без пробела, например «недвижимостиИщем».

**Чего RSS не даёт:**
- числа откликов (на странице ленты оно есть, в RSS нет);
- полного текста ТЗ;
- данных о заказчике.

Вакансии и конкурсы в RSS, судя по всему, не попадают. Сверка: из 30 карточек на https://www.fl.ru/projects/ в `all.xml` не было 13. Четыре из них проверены по карточкам ленты: три вакансии и один конкурс. Официально это не описано, статус — **не подтверждено**.

**robots.txt.** В `https://www.fl.ru/robots.txt` для `User-agent: *` (и отдельно для Yandex и Googlebot) есть `Disallow: */rss/*`. Формально это относится и к RSS. С другой стороны, сам FL в базе знаний предлагает подписываться на эти ленты через RSS-агрегаторы ([БЗ 62073](https://knowledge-base.fl.ru/article/62073), [БЗ 87124](https://knowledge-base.fl.ru/article/87124)), а robots.txt адресован поисковым роботам. Личный бот, который раз в несколько минут читает свои ленты, по смыслу работает как RSS-агрегатор. Вежливость обязательна: интервал ≥ 180 с, не чаще 1 запроса в 2 с. Отдельного разрешения для ботов-агрегаторов в правилах **не найдено**.

**Другие официальные каналы уведомлений** ([БЗ 87124](https://knowledge-base.fl.ru/article/87124), [БЗ 62072](https://knowledge-base.fl.ru/article/62072)):
- ежедневное письмо с заказами по основной специализации;
- Telegram-бот FL @flru_projects_bot — «будет отправлять вам уведомления сразу после публикации заказов».

### 1.3. Отклики для аккаунта без PRO

Подтверждено официальными источниками: [FAQ на https://www.fl.ru/projects/](https://www.fl.ru/projects/), [БЗ 64700 «Отклики на заказы»](https://knowledge-base.fl.ru/article/64700), [Приложение №1 «Перечень платных сервисов»](https://st.fl.ru/about/documents/appendix_1_price.pdf) (ред. от 24.03.2026, п. 4.1.4–4.1.5, 4.2.6), [Приложение №2 «Правила пользования сайтом»](https://st.fl.ru/about/documents/appendix_2_regulations.pdf) (ред. от 13.04.2026, п. 2.2–2.3).

- **PRO не нужен.** «PRO-аккаунт для откликов не нужен (ни для платных, ни для бесплатных)» (FAQ /projects/). «С 06.03.2024 отклики не входят в пакет PRO» (БЗ 64700).
- **Бесплатно:** «можно откликаться на заказы с бейджем «для всех», отвечать на любые вакансии и участвовать во всех конкурсах» (FAQ /projects/). Опцию «для всех» оплачивает заказчик: 1 500 ₽, п. 4.2.6 прайса.
- **Платно:** ответы на заказы без «для всех» требуют купленных откликов (п. 4.1.4 и 4.1.5 прайса):
  - 60 откликов на 60 дней — 4 800 ₽;
  - 30 откликов на 30 дней — 2 400 ₽;
  - 20 откликов на 10 дней — 1 000 ₽ (один раз, если пакеты раньше не покупались);
  - 1 отклик без верификации — 80 ₽ (один раз за всё время).

  Отклик «считается потраченным … в момент нажатия» кнопки отправки. Вернуть его можно, только если заказ заблокирован администрацией. Неиспользованные отклики из пакета сгорают.
- **Верификация обязательна для любых откликов.** «Публикация откликов в заказах и вакансиях, а также участие в конкурсах доступны фрилансерам после верификации» одним из способов: раздел «Финансы» после модерации, статус самозанятого, Альфа ID или Сбер ID (Правила, п. 2.2; [БЗ 78593](https://knowledge-base.fl.ru/article/78593)).
- **Лимиты.** Лимита на число бесплатных ответов на заказы «для всех» в официальных источниках **не найдено** (не подтверждено). Ответ — до 5 000 символов, к нему можно приложить до трёх работ, сроки указываются в календарных днях, цену указывать не обязательно ([БЗ 62056](https://knowledge-base.fl.ru/article/62056)).
- **Автоматизация и шаблоны.** В «Как правильно откликаться на заказы» ([БЗ 62056](https://knowledge-base.fl.ru/article/62056)) к плохим практикам отнесены «Шаблонные ответы» и «Использование скриптов для автоматической рассылки ответов — ответ робота виден сразу». Правила запрещают использовать сайт для «нарушения нормальной работы Сайта» и «массовой публикации … спама» (п. 2.3.4–2.3.5).

**Вывод для бота.** Стоимость отклика определяется так:
- для заказа с меткой «для всех» — 0 ₽ (при верифицированном аккаунте);
- для остальных заказов — > 0 ₽ (нужен купленный отклик).

Официального способа отправки нет, а база знаний не одобряет скрипты автоответов. Поэтому FL работает в режиме **draft**. В карточке полезно показывать метку «для всех», чтобы владелец видел, где отклик бесплатный.

## 2. Kwork

### 2.1. Как получать новые проекты

- **Страница биржи** `https://kwork.ru/projects?c=11` — HTTP 200 без входа, `text/html`. Внутри встроенный JSON со списком `"wants":[…]` и пагинатором (`per_page: 12`, `total: 96` для c=11). Поля элемента (наблюдение): `id, name, description, priceLimit, possiblePriceLimit, max_days, kwork_count, date_create, date_active, date_expire, category_id, user.data.wants_count, user.data.wants_hired_percent` и другие.
  - Время `date_active` — московское. Наблюдение: в 23:46 МСК самый свежий `date_active` был 23:34.
  - `date_active` — это время публикации **или повторного запуска** проекта. Многие проекты в выдаче созданы недели и месяцы назад (`date_create` 2025-11-17 при `date_active` 2026-10-21). Это сходится со справкой: проект активен 1–3 суток в зависимости от бюджета, потом скрывается, и покупатель может «Возобновить показ» ([FAQ 429](https://kwork.ru/faq?role=5&article=429)). Значит, по свежести `date_active` повторно запущенный старый проект выглядит новым. Дедупликация по `id` от повтора защитит. Для оценки возраста можно учитывать и `date_create` (решение — тикет 03).
  - `possiblePriceLimit` в выборке всегда равен 3 × `priceLimit`. Подпись этого поля на сайте («допустимый бюджет»?) рисуется скриптом, и её смысл **не подтверждён**.
- **Подкатегории «Разработка и IT» (c=11)** из встроенного справочника `categories`: 37 Создание сайта, 38 Доработка и настройка сайта, 41 Скрипты, боты и mini apps, 79 Вёрстка, 80 Десктоп-программирование, 39 Мобильные приложения, 40 Игры, 255 Серверы и хостинг, 81 Юзабилити, тесты и помощь.

  Все проверенные страницы отдали HTTP 200 (2026-10-21):

  | Страница | Элементов на странице | Всего (`total`) |
  | --- | --- | --- |
  | c=11 | 12 | 96 |
  | c=41 | 12 | 23 |
  | c=38 | 12 | 20 |
  | c=37 | 12 | 22 |
  | c=80 | 8 | 8 |
  | c=255 | 2 | 2 |

  12 элементов c=11 покрывали около 4 часов вечером. При опросе раз в 5 минут первой страницы хватает.
- **robots.txt** (`https://kwork.ru/robots.txt`): `/projects` не закрыт. Закрыты `/*?page=`, `/*&page=`, `/*?s=`, `/*&s=`, `/search`, `/login` и др. Пагинацию и поиск не используем.
- **Официальные уведомления Kwork:**
  - письма «Новые проекты на Бирже (для продавцов)» с настраиваемым графиком ([FAQ 2619](https://kwork.ru/faq?role=5&article=2619));
  - приглашения на проекты, подобранные алгоритмом, с фильтром по бюджету ([FAQ 2488](https://kwork.ru/faq?role=5&article=2488));
  - браузерные уведомления ([FAQ 2494](https://kwork.ru/faq?role=5&article=2494));
  - мобильное приложение ([FAQ 1586](https://kwork.ru/faq?role=5&article=1586)).
- **Официальный API.** В справке Kwork (`https://kwork.ru/faq`, встроенные статьи) слово «API» не встречается ни разу. Поиск по сети («Kwork API для разработчиков официальный», 2026-10-21) документации не нашёл. **Официального публичного API для продавцов нет.** API мобильного приложения — скрытый, и мы его не используем.

### 2.2. Ограничения из Пользовательского соглашения

[Пользовательское соглашение Kwork](https://kwork.ru/terms_of_service), раздел «Права собственности»: пользователи обязуются не «использовать программное обеспечение для автоматизации (боты), хаки, модификации (моды) или любое другое несанкционированное стороннее программное обеспечение, предназначенное для модификации Сервиса Kwork», а также не «использовать любого робота, паука, поисковые роботы или другое автоматическое устройство, процесс, программное обеспечение или запросы, которые … получают доступ к Сервису Kwork, чтобы отслеживать, извлекать, копировать или собирать информацию или данные из Сервиса Kwork…».

Следствия:
- **Автоотправка на Kwork запрещена соглашением** — не только не подтверждена.
- **Автоматический опрос страницы биржи** (источник Kwork из спецификации, R27) формально подпадает под запрет на «автоматический процесс … чтобы отслеживать … информацию» — даже при том, что robots.txt `/projects` разрешает. Это риск для аккаунта, и решать его должен пользователь (см. «Открытые вопросы»). Официальная альтернатива без нарушения — письма «Новые проекты на Бирже» и приглашения.

### 2.3. Коннекты

Источники: [FAQ 441 «Что такое коннекты»](https://kwork.ru/faq?role=5&article=441), [FAQ 442 «Лимит коннектов меньше, чем должен быть»](https://kwork.ru/faq?role=5&article=442), [FAQ 454 «Закончились коннекты»](https://kwork.ru/faq?role=5&article=454), [FAQ 2488 «Приглашение продавцов на проекты Биржи»](https://kwork.ru/faq?role=5&article=2488), [FAQ 260 «Уровни продавцов»](https://kwork.ru/faq?role=5&article=260), [Пользовательское соглашение](https://kwork.ru/terms_of_service) («Коннект — функциональная единица Сервиса используемая для отправки предложений по проектам Покупателей на Бирже»).

- **Расход:** «Отправка каждого предложения покупателю стоит 1 коннект». Коннект списывается при отправке предложения (FAQ 441).
- **Бесплатно, купить нельзя:** «Коннекты выдаются системой бесплатно, их невозможно купить, заработать дополнительно или получить раньше установленного срока» (FAQ 441).
- **Сколько выдают:** пополнение каждый месяц по уровню продавца:

  | Уровень | Коннектов в месяц |
  | --- | --- |
  | Без уровня | 30 |
  | Восходящая звезда | 50 |
  | Высший рейтинг | 80 |
  | Высший рейтинг плюс | 80 |

  Условия уровней — в FAQ 260.
- **Когда лимит снижается:** за каждые −10 % успешных заказов снимается 25 % лимита. При улучшении показателя коннекты «возвращаются сразу». Обмен контактами ведёт к «обнулению коннектов на бирже»: за 2-е и 3-е нарушение — на 30 дней, дальше — на 1 год (FAQ 442, [FAQ 1054](https://kwork.ru/faq?role=5&article=1054)).
- **Бесплатные отклики:** «мы не списываем коннекты за отклики по приглашениям» (FAQ 2488).
- **Возврат за обычное предложение** (например, если проект удалили) в справке **не описан** — не подтверждено.

Вывод для бота: отклик на Kwork не стоит денег, но тратит ограниченный ресурс (около 30 коннектов в месяц для нового продавца). `kwork.connects_daily_limit = 0` по умолчанию оправдан. Контакты в тексте предложения недопустимы (обнуление коннектов). Это совпадает с `include_contacts = false`.

### 2.4. Требования к аккаунту продавца

- [FAQ 2641 «Правила регистрации и работы продавцов»](https://kwork.ru/faq?role=5&article=2641): «Чтобы создать кворк, сделать отклик на проект и начать работать с заказчиками, продавцу необходимо соответствовать трем условиям»:
  1. гражданство РФ;
  2. статус самозанятого или ИП (или готовность его оформить);
  3. российская банковская карта (для самозанятого) или расчётный счёт (для ИП).

  Обоснование — 289-ФЗ о платформенной экономике, который действует с 01.10.2026. Статус проверяется автоматически, и только после этого можно «откликаться на проекты». По спецификации, в резюме у владельца «Самозанятость: Нет». Если статус не оформлен, откликаться на Kwork не получится.
- В некоторых творческих рубриках для отклика нужно портфолио в этой рубрике ([FAQ 2236](https://kwork.ru/faq?role=5&article=2236)). Для рубрик «Разработка и IT» такого требования не найдено (не подтверждено).
- Шансы на заказ растут от процента найма у покупателя (`wants_hired_percent`), уникального текста, заполненного профиля и портфолио, рейтинга ([FAQ 2204](https://kwork.ru/faq?role=5&article=2204)). Это подтверждает фактор (в) истории 16 спецификации.

```

Запрета на чтение публичных страниц не нашёл. [Оферта](https://freelance.ru/offer.html) про автоматизацию ничего не говорит.

**Вывод для бота.** Режим **draft**, одна страница ленты раз в 10 минут, карточка — один раз и только для нового публичного задания нужного раздела. В промпте нейросети и в подсказках — без ссылок и контактов, текст под задание.

## 6. Work-zilla

**Дата проверки:** 2026-10-24. Операции подключены по просьбе пользователя (ADR 0010); источник выключен, пока аккаунт видит только демонстрационную ленту.

### 6.1. Как получать задания

Операции из `freelance_bot/sources/work-zilla.json` снял пользователь, войдя в аккаунт исполнителя через api-anything:

| Операция | Запрос | Что отдаёт |
| --- | --- | --- |
| `feedStatus` | `GET https://client.work-zilla.com/api/order/v6/list/open?hideInsolvoOrders=false`, cookie сессии, заголовок `agentid` | `data`: `isStaticOrders`, `openOrdersCount`, `haveMoreOrders` |
| `listVisibleOrders` | тот же запрос | `data.other[]`: `id`, `subject`, `description`, `price`, `modified` (мс), `categoryId`, `status`, `archived` |

**Наблюдение 2026-10-24.** В ответе есть ещё `data.interesting` (пуст) и `withoutSubscriptionRenew`, `result` (0 — успех). У аккаунта `isStaticOrders: true`, `openOrdersCount` около 1400, в `other` 50 демонстрационных заданий: `customerId` 0, `categoryId` 0, `status` 2, у всех одинаковое `modified` (2026-10-21). Без cookie — 401. Без `agentid` — 200 и `{"result": 102}`. `agentid` браузер создаёт сам и регистрирует запросом `POST /api/identity/v1/api-agent/save`; в localStorage у него срок около 40 минут, но сервер принимал его и после. Cookie `Bearer` действует до 2027-10-24. Ответ приходит и на User-Agent бота. Ссылки на отдельное задание в ответе нет. Work-zilla сама пишет, что задания (и её Telegram-бот уведомлений) доступны после [обязательных шагов](https://work-zilla.com/freelancers).

### 6.2. robots.txt и соглашение

- `https://client.work-zilla.com/robots.txt` — `User-agent: * / Disallow: /`. Ленту бот читает оттуда, потому что эти операции выбрал пользователь (ADR 0010).
- [Пользовательское соглашение](https://work-zilla.com/users-agreement): поиск по словам «автоматическ», «парс», «робот», «скрипт», «сбор данных» запрета автосбора не нашёл (только автопополнение баланса заказчиком).

**Вывод для бота.** Задания разбираются, только если `isStaticOrders` равно false; демо-лента и ответ без этого поля не сохраняются и не присылаются. Отклики бот не отправляет.

## 8. Открытые вопросы для пользователя

1. **Источник Kwork и Пользовательское соглашение (§2.2).** Автоматический опрос `kwork.ru/projects` противоречит пункту соглашения о роботах и автоматическом сборе данных, хотя robots.txt его разрешает. Есть три варианта:
   - (а) оставить источник выключенным по умолчанию (`sources.kwork.enabled = false`) и получать проекты официальными письмами и приглашениями Kwork;
   - (б) включить на свой риск с редким опросом;
   - (в) убрать источник.

   Решение за пользователем.
2. **FL robots.txt `Disallow: */rss/*` (§1.2).** RSS официально предлагается для агрегаторов, поэтому риск ниже, чем на Kwork. Но явного разрешения для ботов нет.
3. **Верификация на FL** (Финансы / самозанятость / Альфа ID / Сбер ID) нужна для любых откликов, в том числе бесплатных. **Статус самозанятого или ИП** нужен для откликов на Kwork.
