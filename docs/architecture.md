# Архитектура

Один процесс: `python -m freelance_bot run` = long-polling бот + JobQueue по интервалам источников (ADR 0006). Секреты — только `.env` через `freelance_bot/config.py`. Время в БД — UTC ISO-8601, показ и «сегодня» для лимитов — Europe/Moscow.

## Поток данных

`Source.fetch()` -> `Storage.upsert_project` (дедуп по platform+external_id; только новые идут дальше) -> bootstrap -> `scoring.score_project` -> отсечение -> `policy.decide_mode` -> `drafting` -> `Notifier` -> статусы и `responses`. Код цикла: `freelance_bot/pipeline.py` (`Pipeline.run_once`, `_run_source`, `_deliver`).

- Bootstrap: при первом запуске площадки (флаг `bootstrapped:<platform>` пуст) проекты старше `general.max_age_hours` получают `filtered_out` с note `bootstrap` без уведомлений.
- Отсечения (статус `filtered_out`, причина в note): не прошёл `min_score` или исключён (`excluded_reason`); FL без метки «для всех» при `only_free_responses` (note «платный отклик»).
- Проходящие сортируются по баллу; `notify` — только карточка; `draft` — карточка + черновик; `auto` — `decide_mode` вызывается дважды (до и после генерации черновика: метки `[ЦЕНА]` и т.п. переводят в draft).
- Сбой источника: `BlockedError` -> флаг `blocked_until:<platform>` (пауза BLOCK_PAUSE) и одно сообщение; прочие ошибки -> `fail_count`, одно сообщение на серию (FAILURES_BEFORE_ALERT). Цикл не падает.
- Кнопки карточки (`applied:/skip:/redraft:/offer:<platform>:<id>`) обрабатывает `bot.py`; `redraft` -> `Pipeline.redraft` (счётчик варианта во флаге `variant:<p>:<id>`).
- `/last` -> `Pipeline.offer_candidates`: проекты за `OFFER_WINDOW` (7 дней) без статусов applied/skipped/sent, балл считается на момент публикации (возраст и bootstrap не отсекают), платные FL — по `only_free_responses`.
- Цена и срок: `offer` (кнопка или список `/last`) ставит флаг `awaiting_offer` = `<p>:<id>`; следующее текстовое сообщение владельца разбирает `bot.parse_offer`, `Pipeline.offer` берёт последний черновик (`Storage.latest_response`, нет — генерирует) и `drafting.fill_offer` подставляет значения. Ответ — текст в `<pre>` и URL-кнопка на проект; на биржу ничего не уходит, статус меняет только «Откликнулся».

## Границы модулей

- `models.py` — frozen-датаклассы `Project`, `ScoreResult`, `Draft`, `ModeDecision`; без ввода-вывода.
- `config.py` — `load_settings(settings.toml, .env) -> Settings`; интервал источника < 60 с поднимается до 60; `ConfigError`.
- `http.py` — `Fetcher` (таймаут, ретраи, пауза между запросами к домену, Retry-After), `looks_blocked`; ошибки `SourceError` > `TemporarySourceError`, `BlockedError`, `HttpStatusError` (4xx, `.status`).
- `sources/` — `fl.py` (`parse_fl_rss`, `FlSource`), `kwork.py` (`parse_kwork_projects`, `KworkSource`), `api_anything.py` (исполнитель операций API Anything: `load_operations`, `operation_request`, `extract_json`/`extract_json_object`, `extract_html`/`extract_html_items` на CSS-селекторах с `#id` и `@атрибутом`), `work24.py` (`Work24Source`, операции `work24.json`; карточки только для новых ID — `known` из `Storage`), `freelance_ru.py` (`FreelanceRuSource`, `freelance-ru.json`: первая страница `/task`, разделы `categories`, без «Только для Премиум», контакты из текста вырезаются; ADR 0010), `workzilla.py` (`WorkzillaSource`, `work-zilla.json`, сессия пользователя; демо-лента `isStaticOrders` → `DemoFeedError`, ничего не сохраняется; ADR 0010), `superjob.py` (`SuperJobSource`: официальный API `/2.0/vacancies/` с ключом `X-Api-App-Id`, по запросу на слово `queries`, вакансии как у HH; ADR 0012), `trudvsem.py` (`TrudvsemSource`: открытые данные «Работы России» без ключа, регион города — `region_for`, город вакансии из адреса; только под анкету; ADR 0015), `tgchannels.py` (`TgChannelsSource`: веб-превью `t.me/s/<канал>` без аккаунта, каналы и их города — `channels`, вакансия — пост с «Обязанности»/«Требования», контакты отрезаются, ID — хэш текста; только под анкету, без нейросети; ADR 0016), `hh.py` (`HhSource`: вакансии из чата пользователя с ботом HH @hh_rabota_bot; `TelethonReader` — сессия Telegram, только чтение; `parse_notice` разбирает подборку Хэдди; ключ — `vacancy_key`, ADR 0009); парсеры — чистые функции; неожиданная структура -> `SourceFormatError`.
- `textmatch.py` — `find_terms`, единственный способ сопоставлять ключевые слова (scoring и исключения). Перед регуляркой — отсев по подстроке (`_fold`: регистр так, как его сравнивает `re.IGNORECASE`, вместе с «İ» и парами вроде «ᲀ»/«в»); результат тот же, подбор в 5–7 раз быстрее.
- `progress.py` — прогресс подборки списка (`Tracker`, `Progress`): сообщение «⏳ … ▰▰▱▱ 40%» появляется, если подборка дольше 1,5 с, правится не чаще раза в секунду и удаляется, когда список пришёл; повторное нажатие, пока подборка идёт, получает «уже ищу — N%».
- `scoring.py` — балл 0..100: направления, пересечения, свежесть, бюджет, offers_count, штраф за требования к исполнителю, поправка отметок пользователя (`learning.apply`) и смысла должности под резюме (`fit.apply`); `extract_client_requirements`. Веса — константы в файле.
- `fit.py` — смысл должности под резюме анкеты (ADR 0018): `ResumeFit.build` (основа должности, уточнения, сфера, специализация, уровень — из профессии, прошлых должностей и мест работы), `apply` — по названию вакансии и компании: точная должность +15, чужая специализация −25, чужая сфера у администратора/управляющего/менеджера — отсечение, уровень выше резюме — отсечение. Словари `SPHERES`, `SPECIALTIES`, `TOP_LEVELS` — константы в файле. В `Settings.fit` его кладёт `matching.user_settings`.
- `learning.py` — самообучение (ADR 0013): «👎 Не подходит» + причина (`REASONS`) → правило (`learn`), его действие на балл и отсечение (`apply`), тексты (`describe`). `experience.py` — требуемый стаж в тексте («опыт коммерческой разработки от 3 лет» → 3) для штрафа скоринга и правила «не мой уровень». Правила — в `Settings.lessons`, их подставляет `Pipeline.scoring_settings` (владелец) и `first_matches(tg_id=…)` (анкета); у каждого резюме свои (`lessons.scope` = `matching.lesson_scope`, ADR 0018).
- `storage.py` — SQLite (`projects`, `responses`, `flags`, `events`, `users` — анкеты публичного бота, `lessons` — правила из отметок, ADR 0013, со `scope` резюме, `user_marks` — показанные человеку вакансии и его отметки «откликнулся»/«не подходит» с копией вакансии, ADR 0018), миграции через `PRAGMA user_version`; `/forget` (`delete_user`) удаляет анкету, правила и отметки; флаги: `paused`, `last_ok:`, `last_error:`, `blocked_until:`, `bootstrapped:`, `fail_count:`, `variant:`, `awaiting_offer`, `summary:`, `digest_last_at` (время последнего списка новых).
- `profile.py` + `profile/profile.toml` — подтверждённые факты (`Fact.source` — дословная строка резюме), `forbidden_claims`; контакты по умолчанию не попадают в отклики.
- `summary.py` — суть заказа для карточки и `/last`: `LlmSummarizer` (Claude, effort low) или `builtin_summary` (первые предложения); `CachedSummarizer` кэширует удачную суть во флаге `summary:<p>:<id>`, запасную — нет.
- `drafting.py` — `BuiltinDrafter` (шаблоны), `LlmDrafter` (Groq, GPT или Claude, необязателен, при сбое или нарушении откат на builtin), `validate_draft`, `similarity` (порог 0.6 против `recent_drafts`). Контекст заказа для нейросети — `brief_block` (заголовок, раздел, ТЗ; обрезанное RSS FL помечено, длиннее `BRIEF_MAX_CHARS` — начало и конец) и `_order_facts` (площадка, бюджет, срок, отклики); факты опыта — `rank_facts` (ближайшие к ТЗ сверху).
- `policy.py` — `decide_mode`; `SENDERS` пуст.
- Вакансии (`telegram_ui.VACANCY_PLATFORMS`, сейчас `hh`): карточка `format_vacancy_card` (компания, город, зарплата, время уведомления), кнопки только «Откликнулся»/«Пропустить», выбор в списке присылает карточку со ссылкой вместо черновика, суть — без LLM (`summary.BUILTIN_ONLY`).
- `onboarding.py` — анкета публичного бота (ADR 0011): `Onboarding` (шаги в `users.step`, кнопки `ob:…`), разбор резюме — фоновой задачей; `resume.py` — `extract_text` (PDF, DOCX, TXT), `fetch_link` (только Google Docs/Диск, Яндекс Диск), `analyze` (нейросеть, всё сверяется с текстом резюме; иначе `builtin_profile`): профессия, город, стаж по периодам мест работы, места работы, навыки, образование, направления и слова; контакты не хранятся и нейросети не отправляются (`_without_contacts`). `bot.py` направляет в анкету посторонних (`_is_public`) и владельца после `/signup`. Под списком анкеты — кнопки отметок `ob:ap|nf|nr:<площадка>:<id>` (`matches_markup`); у владельца «🔎 Предложения по анкете» — тот же список и кнопки, что «📋 Все предложения» (`BotHandlers.owner_matches`, `Pipeline.offer_candidates`, без живого поиска: собранное под его анкету уже в базе), его прежние отметки `ob:ap|nf` из списка убирают, `/learned` пользователя — `ob:ul:…` (ADR 0018); не разработчику — «✏️ Профессия» (`profile.roles`) вместо IT-направлений; ФИО шапки резюме (`resume.person_name`) не совпало с анкетой — `data.resume_name` и предупреждение.
- `cover_letter.py` — письмо к вакансии (ADR 0017): `Applicant` из анкеты (`applicant_from_anketa`) или `profile.toml` (`applicant_from_profile`), `CoverLetterWriter.write` — нейросеть с `letter_problems` (стаж, контакты, опыт из вакансии, которого нет в резюме — `unconfirmed`, ADR 0018) и одним исправлением, иначе `builtin_letter`; `tgchannels` — всегда шаблон. Кнопка `letter:<площадка>:<id>` — `BotHandlers._letter`, последний вариант — флаг `letter:…`.
- `matching.py` — подбор под анкету (ADR 0014): `user_settings` (направления разработчика или профессия и навыки из резюме), `mismatch` (стаж, город и удалёнка по `data.location`, вахта и «с проживанием» в тексте, профессия), `rank` (свой город, свежие за `FRESH_FIRST`, балл), `drop_repeats` (одна вакансия и на разных площадках), `group_chains` (сеть с той же должностью в разных городах — одной строкой), `lesson_scope`, `VacancySearch` — живой поиск `SuperJobSource(town=…)` и `TrudvsemSource(city=…)` по словам профессии и чтение каналов города `TgChannelsSource`, параллельно; вызывается из `Onboarding._send_matches`, результат идёт в `first_matches(extra=…)` вместе с собранным. `AnketaVacancies` — источник сбора владельца (superjob, trudvsem, tgchannels) под его пройденную анкету; `Pipeline.scoring_settings()` и `outside_anketa` делают его ленту, `/last` и дайджест анкетными (ADR 0015), время дайджеста — расписание анкеты (`BotHandlers.digest_tick`, не больше `DIGEST_LIMIT` за раз; ADR 0018). `VacancySearch(…, statuses=)` сообщает ответ каждой площадки — для текста пустого списка.
- `telegram_ui.py` — форматирование HTML-карточек без сети; `bot.py` — хэндлеры с фильтром владельца, `TelegramNotifier`; `__main__.py` — CLI и `RedactingFormatter`.
- `guide.py` — описание бота в профиле Telegram (ставится при запуске, только если текст другой: `bot._register_description`) и справка `/help` / «❓ Помощь»: оглавление и разделы кнопками `help:<тема>`, сообщение меняется на месте; у владельца и у пользователя анкеты разделы разные.

## Соглашения

- Тесты не ходят в сеть: `Fetcher(transport=httpx.MockTransport)`, фикстуры `tests/fixtures/`, `Storage(":memory:")`, время инъектируется (`score_project(..., now=)`, `clock=`).
- Только публичные GET и официальный RSS; без логина, обхода CAPTCHA, скрытых API (исключения — ленты Work24 из `api.work24.ru` и лента Work-zilla сессией пользователя, по его просьбе, ADR 0008, 0010); вакансии HH — не с сайта, а из сообщений бота HH в Telegram пользователя, только чтение (ADR 0009); ничего не покупает и не тратит коннекты сверх `kwork.connects_daily_limit` (0).
- Автоотправка (`auto`) возможна только если одновременно: есть `Sender` с `official_confirmed`, отклик бесплатный, заданы `offer.price_rub` и `offer.days`, `daily_auto_limit` > 0 и не исчерпан, для Kwork — лимит коннектов, не dry-run. Иначе `effective=draft` с причинами. Сейчас `SENDERS` пуст, поэтому всегда draft (ADR 0001).
- Тексты для пользователя — по-русски. Зависимости менять нельзя без решения пользователя.
- Решения и причины: `docs/adr/`; термины: `CONTEXT.md`; проверка площадок: `docs/platforms.md`.
