## Контекст
2026-10-24 пользователь решил сделать бота публичным: «сохраняем всю логику, которая есть сейчас, и добавляем вступительную логику». По /start бот спрашивает ФИО, как обращаться и резюме (PDF, doc или ссылка), выделяет из резюме критерии поиска, показывает подключённые площадки и даёт выбрать, где искать, или нажать «Везде». Работаем поэтапно.

Это отменяет прежнюю договорённость «Свой бот у каждого… общий бот с регистрацией не делать» (`.autopilot/PROGRESS.md`). Пользователь выбрал «Этот же бот», а не отдельный публичный: сбор с площадок идёт один раз на всех.

Что мешает просто открыть бота:
- Бот рассчитан на одного человека: один `owner_id`, один `profile.toml`, статусы заказов, черновики и флаги в базе общие.
- ФИО и резюме посторонних — персональные данные (152-ФЗ): нужно согласие и возможность удалить.
- Текст резюме для разбора уходит нейросети (Groq, OpenAI или Anthropic — все в США).
- Ссылку на резюме присылает посторонний, а скачивает сервер. Произвольный адрес — это SSRF.
- Площадки. Kwork пользователь не предлагает («давай пока без kwork»: соглашение запрещает автосбор, ADR 0003). Work-zilla работает на сессии владельца и выключен. HH сейчас читается из личного чата владельца с Хэдди (ADR 0009) — другим так дать нельзя.

## Решение
Три этапа.

1. **Анкета и хранение** (этот ADR, `freelance_bot/onboarding.py`, `freelance_bot/resume.py`).
2. Рассылка каждому: заказы собираются один раз, балл и отбор считаются по анкете пользователя.
3. Черновики под профиль пользователя и лимиты нейросети.

Анкета: согласие → ФИО (2–4 слова буквами) → обращение (кнопки «Имя», «Имя Отчество», свой вариант) → резюме → «вот что я понял» → направления (по желанию) → площадки (всё включено, переключатели, «Везде») → частота уведомлений. Частота (`freelance_bot/schedule.py`): по умолчанию раз в час с 9 до 21 («Раз в час (по умолчанию) — с возможностью замены на свой тайминг», 2026-10-24); ещё «2 раза в день» (10:00, 18:00), «Раз в день» (10:00) и свой тайминг текстом — время по часам («10:00, 14:30», до 12 раз) или интервал в окне дня («каждые 30 минут с 8 до 23», не чаще раза в 15 минут). Время — по `general.timezone`. Сменить частоту можно и после анкеты (кнопка в /start), анкета остаётся пройденной. Состояние анкеты — таблица `users` (миграция 2): шаг, JSON с данными, время согласия и завершения. Анкета переживает перезапуск. «Заполнить заново» снимает отметку завершения, чтобы этап 2 не слал рассылку по половине анкеты.

- Включается `[public] enabled` в `settings.toml` (по умолчанию false: посторонним прежний отказ). Площадки анкеты — `[public] platforms` (сейчас FL.ru, Freelance.ru, Work24, HH).
- Владелец работает как раньше, но `/start` и у него сразу открывает анкету — и при выключенном публичном режиме («когда я нажимал на старт… сразу переходить к анкете», 2026-10-24); заново — `/signup`, прежнее меню владельца — `/menu`. Его `profile.toml` при этом не меняется, меню владельца работает посреди анкеты.
- Посторонним команды владельца закрыты: им приходит подсказка `/start`, `/profile`, `/forget`. В публичном режиме меню команд для всех — только эти три, владельцу в его чате — полное (`BotCommandScopeChat`).
- Согласие называет, что собирается и куда уходит текст резюме (нейросеть называется, только если ключ задан). `/forget` удаляет строку целиком. Файл резюме не хранится — только выжимка: направления, слова, стаж, факты.
- Резюме: PDF (`pypdf`, новая зависимость), DOCX (zip + `defusedxml`, без новой зависимости), TXT (UTF-8 или cp1251), текст сообщением (от 300 символов). `.doc`, `.rtf`, `.odt` — просьба пересохранить, чтобы не ставить LibreOffice в образ. Файл до 10 МБ, PDF до 20 страниц, `document.xml` до 5 МБ (zip-бомба). Скан без текста — понятная ошибка.
- Ссылки: только Google Docs (экспорт txt), Google Диск и Яндекс Диск (публичный API). HTTPS, переадресации только на эти домены, потолок размера. Ссылки hh.ru не открываются — подсказка скачать PDF в «Мои резюме» (условия hh.ru, ADR 0009).
- Разбор: нейросеть (та же, что для черновиков, `make_llm_client`) возвращает JSON. Код оставляет направления только из `settings.directions`, ключевые слова — только найденные в резюме, факты — только с дословной строкой резюме (как ADR 0005). «Делал ботов» — только если в резюме есть такие слова. Нет ключа или ответ не разобран — встроенный разбор: направления и слова по ключевым словам `settings.toml` (показываются словами резюме, а не основами), стаж — по строке «Опыт работы — N лет M месяцев». В нейросеть уходят первые 5000 символов: с ответом запрос влезает в 8K токенов в минуту Groq.
- Не больше 5 разборов в день на человека. Разбор идёт фоновой задачей (`Application.create_task`), чтобы минута ожидания нейросети не задерживала других. Пока он идёт, шаг `analyzing`, повторный файл не принимается.

## Почему
- Отдельный бот: сбор с площадок шёл бы дважды (нагрузка и риск блокировки ×2). Пользователь выбрал этот же.
- Сессии Telegram пользователей для HH, как у владельца: это полный доступ к чужим аккаунтам. Отклонено. Как давать HH другим — открытый вопрос (ниже).
- Произвольные ссылки на PDF: сервер ходил бы куда скажет посторонний (SSRF). Отклонено.
- python-docx: тянет lxml. DOCX — это zip с XML, а `defusedxml` уже в зависимостях.

## Последствия
- До этапа 2 анкета ничего не присылает: в конце — «подборки начнут приходить, когда включим рассылку». На сервере `[public] enabled = false`, пока нет этапа 2.
- Оператор персональных данных — владелец бота. Уведомление Роскомнадзора и политика обработки — его решение, бот только собирает согласие.
- HH в анкете можно выбрать, но для посторонних он пока не работает. Telegram Business (боты-секретари) проверен 2026-10-24 и отпал: Bot API принимает бота (`can_connect_to_business=True`), а приложение без Telegram Premium подключить его не даёт — до чтения чата с Хэдди проверка не дошла. Остаётся официальный API HH: регистрация приложения на dev.hh.ru, условия API п. 1.4 — галочка о соглашении hh.ru.
- Новая зависимость `pypdf` 6.20.0 (BSD-3-Clause, чистый Python), закреплена в `deploy/constraints.txt`.
