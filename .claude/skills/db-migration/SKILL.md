# Миграция базы

Схема — кортеж `MIGRATIONS` в `freelance_bot/storage.py`: каждый элемент — SQL-скрипт,
номер версии = индекс + 1, текущая версия базы — `PRAGMA user_version`. `Storage._migrate`
при открытии базы выполняет недостающие скрипты по одному в транзакции. Боевая база уже на
последней версии — **её старые скрипты больше никогда не выполнятся**.

## Шаги

1. **Посмотреть, что есть:** `MIGRATIONS` и все запросы к затронутым таблицам
   (`grep -n "<таблица>" freelance_bot/*.py`), модели в `freelance_bot/models.py`,
   описание схемы в `docs/architecture.md` («storage.py»).
2. **Только новый скрипт в конец `MIGRATIONS`.** Существующие скрипты не править и не
   переставлять — на сервере они уже применены, правка в них туда не дойдёт. Над скриптом —
   комментарий: зачем таблица/столбец и ADR, если есть.
3. **Аддитивно:** новая таблица, столбец с `DEFAULT` или `NULL`, новый индекс. Удаление или
   переименование столбца в SQLite — пересборка таблицы (`CREATE TABLE new …; INSERT INTO new
   SELECT …; DROP TABLE old; ALTER TABLE new RENAME TO old`) в одном скрипте; сначала
   убедиться, что старое поле больше никто не читает.
4. **Ограничения в схеме, а не только в коде:** `NOT NULL`, `PRIMARY KEY`/`UNIQUE` там, где
   дубль невозможен (как `PRIMARY KEY (platform, external_id)` у `projects`), `CHECK` для
   статусов и диапазонов. Время — текст UTC ISO-8601 (`_utc_iso`), «сегодня» — по
   `Storage._tz` (МСК).
5. **Индексы — под реальный запрос** (фильтр, сортировка, соединение в коде), не впрок.
6. **Персональные данные** (всё, что связано с `users.tg_id`): `Storage.delete_user`
   (`/forget`) должен удалять и строки новой таблицы — в одной транзакции. Файлы резюме не
   хранить, только выжимку (ADR 0011).
7. **Тесты** в `tests/test_storage.py`:
   - свежая база (`Storage(":memory:")`) — новая схема и `PRAGMA user_version == len(MIGRATIONS)`;
   - база **предыдущей версии** с данными: создать её скриптами `MIGRATIONS[:-1]` и
     `PRAGMA user_version = len(MIGRATIONS) - 1`, вставить строки, открыть `Storage` —
     данные целы, новая схема на месте;
   - `/forget` чистит новую таблицу.
   ```bash
   .venv/bin/python -m pytest -q tests/test_storage.py
   make check
   ```
8. **Документация:** таблицы и флаги в `docs/architecture.md`; решение о модели данных —
   навык `adr`.
