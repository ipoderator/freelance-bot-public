# Закрыть задачу

Запускать после того, как правка работает, — не чтобы прикрыть падающую проверку.

## Шаги

1. **Проверки.** `make check` (ruff + весь pytest) — зелёный; число тестов — в отчёт.
   Падает — чинить причину, а не тест. Сеть (`once`, `run`) в проверках не нужна.
2. **Граф кода:** `graphify update .` (только AST, без затрат).
3. **Документация — только то, что стало неправдой:**
   - `AGENTS.md` — команды, «Где что», «Подводные камни» (новая ловушка — одна строка);
   - `docs/architecture.md` — границы модулей, таблицы, флаги;
   - `docs/platforms.md` — факты о площадке (навык `known-issue`);
   - `CONTEXT.md` — новые термины;
   - `docs/adr/` — если принято архитектурное решение (навык `adr`);
   - `settings.toml` — комментарий над изменённой настройкой: дата и чьё решение.
5. **Личное и секреты.** В тестах только вымышленные имена (проверка утечек ловит строки
   своего резюме); новый файл с личными данными — в метки `>>> private` / `<<< private` или в
   `EXCLUDE` `scripts/public_export.py`; `.venv/bin/python -m pytest -q tests/test_public_export.py`.
6. **Обзор диффа:** `git status --short` и `git diff --stat`, затем `git diff` по каждому
   файлу: нет посторонних правок, отладочных print, секретов.
7. **Коммит** — только если пользователь попросил, навыком `commit-push`.

## Отчёт (по-русски)

- что сделано и где (`файл:строка`);
- чем проверено: команды и числа (`make check` — N passed);
- что не сделано или не проверено (сеть, сервер, живая лента) — прямо;
- что нужно от пользователя (ключ, вход, решение).
