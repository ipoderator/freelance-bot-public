## Контекст
2026-10-25 владелец прошёл анкету с резюме продавца-консультанта (ADR 0011, 0014) и написал: «во-первых не ищет по всем сайтам, которые есть, а во-вторых выводит мои старые вакансии и работы. То есть я загрузил резюме продавца консультатна, а он выводит мне бэкэнд разработчика».

Разобрано по логу сервера 2026-10-25: под анкету пришла одна подборка (5 вакансий, IT-вакансии продавцу в неё не проходят — `matching.mismatch`). Бэкенд пришёл из меню владельца («📋 Все заказы», «🆕 Новые», дайджест): они отбирали по `settings.toml` и `profile.toml` разработчика, анкета на них не влияла («`profile.toml` анкета не трогает», ADR 0011). Площадка у продавца одна: ленты FL.ru, Freelance.ru и Work24 настроены на IT-разделы, HH выключен (сессия отозвана), из вакансий остался SuperJob, а он в небольших городах почти пуст (ADR 0014).

На вопрос о меню пользователь выбрал «Меню по анкете», о площадках — «Добавить «Работа России»» (2026-10-25).

Проверено 2026-10-25 (`docs/platforms.md`, §8):
- `trudvsem.ru/opendata/api` — API портала «Работа России» для открытых данных («Методические рекомендации… по публикации открытых данных»), только `GET`, JSON, без ключа; до 100 записей на страницу, `offset` — номер страницы, свежие по дате изменения сверху; параметры `text`, `modifiedFrom`, `regionCode` (путь `/vacancies/region/<код КЛАДР>`). Справочника регионов в API нет (`/dictionaries/regions` — 404), фильтра по городу нет.
- `opendata.trudvsem.ru/robots.txt` — `User-agent: *`, `Disallow: /` («блокировка любого доступа»): хост закрыт для роботов-индексаторов, хотя документация зовёт программы именно туда.
- Поиск `text=<город>` находит вакансии с этим городом в адресе: Елец — 20 из 20, регион «Липецкая область» (4800000000000); Воронеж, Курск, Тамбов — так же.
- `text=продавец` в Липецкой области — 386 вакансий, за 14 дней — 284; среди первых 100 — 14 в Ельце (на SuperJob в Ельце — 0, ADR 0014). Удалённая работа — поле `employment` «Дистанционная (удаленная) работа». Запрос — ~5 с и ~390 КБ на 100 записей.

## Решение
**Меню по анкете.** Анкета владельца пройдена (`users.completed_at`) — `Pipeline.scoring_settings()` берёт настройки анкеты (`matching.user_settings`: профессия и навыки или выбранные IT-направления, стаж из резюме) с правилами его отметок, а сбор, `/last` («📋 Все заказы»), «🆕 Новые» и дайджест ещё и отсекают то, что анкете не подходит (`matching.outside_anketa`: площадка не выбрана в анкете, `mismatch`). Очередь дайджеста перед отправкой сверяется заново. Анкета заполняется заново или не пройдена — всё по `settings.toml`, как раньше. Черновики откликов по-прежнему пишутся по `profile.toml`.

**Вакансии под анкету при сборе.** Источник `matching.AnketaVacancies` для `superjob` и `trudvsem`: каждый цикл площадки ищет вакансии по профессии и городу из анкеты владельца тем же поиском, что и подборка после анкеты (`VacancySearch`, кэш 10 минут). Без анкеты — ничего не ищет.

**«Работа России»** (`freelance_bot/sources/trudvsem.py`, площадка `trudvsem`, `VACANCY_PLATFORMS`): регион узнаётся у API по названию города (самый частый регион среди вакансий с городом в адресе, кэш в памяти); затем по слову профессии в регионе за 14 дней (`modifiedFrom`), до 2 страниц по 100; по стране — одна страница и только если в анкете выбраны другие города. Слов поиска — 2 (текстовый поиск широкий). Город вакансии — из адреса («г Елец»), а не регион: иначе «липецк» нашёлся бы в «Липецкая область» у вакансии в Ельце. Контакты работодателя не берутся. Карточка — как у SuperJob, дата — «обновлена» (API отдаёт дату изменения). SuperJob и «Работа России» опрашиваются параллельно; сбой одной площадки не теряет вакансии другой. `[sources.trudvsem]` включён, раз в 30 минут; своих слов поиска у владельца там нет. Площадка — в анкете (`[public] platforms`).

## Почему
- Подписать меню «по профилю владельца» и оставить как есть — пользователь выбрал меню по анкете; анкета у владельца — проверка того, что увидит посторонний.
- Переключатель «как разработчик / по анкете» — лишняя кнопка; вернуться к поиску разработчика — пройти анкету с резюме разработчика.
- Показывать продавцу биржи фриланса — их ленты в IT-разделах, пришло бы пусто.
- API HH — заявка не подана, модерация (PROGRESS.md); «Работа России» доступна сейчас, без ключа и с вакансиями в малых городах.
- robots.txt хоста — запрет для индексаторов; API опубликован государством именно для программ, бот только читает, по запросу на слово и не чаще раза в 30 минут — решение пользователя, как Work24 (ADR 0008).

## Последствия
- У владельца с пройденной анкетой продавца заказы бирж в меню и дайджесте не приходят: их площадки не в анкете. Сбор бирж при этом идёт, как раньше.
- Подборка после анкеты ждёт самую медленную площадку: «Работа России» — регион (~5 с) и до 4 запросов по ~5 с.
- Если API сменит формат — `SourceFormatError` («ответ API — не JSON», «нет списка vacancies»); 403 — пауза площадки на час, как блокировка. Регион города, которого API не находит, — пусто (по стране такие вакансии всё равно отсеклись бы по городу).
- Вакансии из сёл получают в `area` название села («Панино село»): человеку из Липецка они не приходят как «другой город».
- Публичным пользователям рассылки по анкете ещё нет (этап 2, ADR 0011): «Работа России» у них — в подборке после анкеты и по кнопке «Заказы по анкете».
