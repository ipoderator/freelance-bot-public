## Контекст
Пользователь попросил добавить вакансии HH.ru: Python, backend, FastAPI, Telegram-боты, AI/LLM, интеграции, автоматизация. Токена API HH у него нет. Сначала нужно было проверить, можно ли получать вакансии без токена через `goodnight000/api-anything` (так подключён Work24, ADR 0008), при этом не обходить CAPTCHA и блокировки. Если постоянный сбор недоступен, подключить уведомления HH о сохранённом поиске.

Проверено 2026-10-24 (`docs/platforms.md`, §4):
- `GET https://api.hh.ru/vacancies` без токена возвращает `403 forbidden`, в том числе с `HH-User-Agent`. Для доступа нужно регистрировать приложение на dev.hh.ru и проходить модерацию.
- Страница поиска `hh.ru/search/vacancy?text=…` отдаёт обычному HTTP-клиенту 200 и 20 вакансий в HTML (~1,4 МБ). Сайт стоит за DDoS-Guard и антифродом Group-IB. Но `robots.txt` для всех роботов закрывает `*?*` (весь поиск) и `/rss/*`. Условия сайта, п. 6.1.38: «не производить автоматизированный сбор и структурирование информации с Сайта при помощи программ или сервисов парсинга, скрапинга или их аналогов»; п. 6.2.2: программы должны работать через API. API Anything повторяет именно такие запросы страниц, поэтому разовая успешная загрузка не делает этот способ допустимым постоянным сбором.
- Письма автопоиска пользователю не приходят.
- Бот HH в Telegram @hh_rabota_bot («Хэдди») присылает подборки и уведомления сохранённых автопоисков. Это официальный канал HH. У пользователя 8 автопоисков с включёнными уведомлениями.
- «Работа России» (`opendata.trudvsem.ru`) отвечает без токена, но это не вакансии HH. По запросу «python» там в основном аналитики и инженеры, около 5 свежих в день.

## Решение
Источник `hh` (`freelance_bot/sources/hh.py`) читает чат пользователя с @hh_rabota_bot через его сессию Telegram (Telethon, `HH_TG_API_ID`, `HH_TG_API_HASH`, `HH_TG_SESSION` в `.env`). Сессию создаёт разовая команда `python -m freelance_bot hh-login`: по умолчанию вход по QR-коду, запасной вариант — `--code`. Источник только читает последние 50 сообщений: ничего не отправляет, кнопок не нажимает, прочитанными не отмечает. Подборки Хэдди разбираются в общий `Project` (`platform="hh"`). Зарплата, если указана, в рублях идёт в поля бюджета, компания и город — в `extra`. Ключ вакансии — хэш «название | компания | город», потому что ссылки в подборке короткие и персональные (`my.hh.ru/b/…`), без ID вакансии. Дальше работает общий пайплайн: дедупликация по ключу, скоринг, дайджест и карточка с компанией, зарплатой, датой уведомления и причиной совпадения. Режим `notify`: черновиков, цены и срока для вакансий нет, отклик пользователь делает на hh.ru сам. Суть вакансии — начало описания, без нейросети.

## Почему
- API Anything / парсинг hh.ru: запрещено п. 6.1.38 условий и закрыто `robots.txt`. Пользователь просил не маскировать проблему обходными приёмами. Не подошло.
- Официальный API: нужен токен приложения после модерации dev.hh.ru, а его нет. Это остаётся самым надёжным вариантом на будущее.
- Письма автопоиска по IMAP: писем нет.
- Бот бота: Telegram-бот не видит сообщений другого бота, поэтому нужен клиент на аккаунте пользователя.
- Отправлять Хэдди номера поисков, чтобы он показал новые вакансии: это автоматизация действий в сервисе HH от имени пользователя и обход того, что Хэдди присылает сам. Не делаем.

## Последствия
- Бот получает только то, что Хэдди сам кладёт в чат: подборки по запросу пользователя и уведомления автопоисков. Какие уведомления и как часто Хэдди присылает без запроса, проверено наблюдением (`.autopilot/PROGRESS.md`). Если он присылает только счётчики («38 новых»), вакансии появятся в боте после того, как пользователь сам откроет подборку в чате с Хэдди.
- В подборке нет даты публикации: в карточке стоит время уведомления. Зарплата есть, только если её указал работодатель. Обязанности и требования обрезаны Хэдди («…»).
- Сессия даёт полный доступ к аккаунту Telegram. Она хранится только в `.env` (права 600), в логах вырезается `RedactingFormatter`, отзывается в Telegram → Настройки → Устройства → «freelance-bot (HH)». Одну сессию нельзя одновременно использовать на Mac и на сервере: Telegram отзывает её (`AUTH_KEY_DUPLICATED`).
- Ошибки: `FloodWait` → пауза без запросов до конца ожидания (`TemporarySourceError`); отозванная сессия → `SourceError` с подсказкой `hh-login`, повторных подключений до перезапуска нет; сообщения с признаками подборки, из которых ничего не разобрано, → `SourceFormatError` («сменился формат»). Через три сбоя подряд приходит одно предупреждение (общий механизм пайплайна).
- Новая зависимость: `telethon` (и `pyaes`, `rsa`, `pyasn1`); `qrcode` — только для `hh-login`, extra `login`.
